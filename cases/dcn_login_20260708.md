# 当乐网 (d.cn) 登录请求分析 — 本地复现

## 基本信息

- 目标名称：当乐网账号密码登录（oauth.d.cn）
- 目标类型：Web 登录接口 / 密码字段加密 (RSA)
- 日期：2026-07-08
- 负责人：逆向实测（crypto-hunter-lite）

## 问题描述

- 现象：访问 `https://oauth.d.cn/auth/goLogin.html`，提交账号密码时，密码并非明文，服务端返回 `{"code":9999,"error":"请先完成图形验证","showValid":true}`。
- 失败表现（直接发明文密码）：服务端无法识别，且正常流程前还强制图形验证。
- 复现步骤：
  1. 打开登录页，注入账号、密码。
  2. 触发 `#pwdLgn button` 点击提交。
  3. 在 listener 中捕获 `GET /auth/login?display=web` 请求，发现 `pwd` 为 256 hex（128 字节）密文，`name` 为明文账号。

## 证据

- 目标请求：
  ```
  GET https://oauth.d.cn/auth/login?display=web
      &name=<明文账号>
      &pwd=<256 hex / 128 字节 RSA 密文>
      &to=https://www.d.cn/
      &reqId=<服务端下发>
      [&geetest_challenge / geetest_validate / geetest_seccode]   # 仅 flag=true 时需要
  ```
- 关键参数：
  - `name`：明文账号
  - `pwd`：RSA(PKCS#1 v1.5, 1024-bit) 加密后的密码，hex 编码
  - `reqId`：来自 `/auth/needGtCode` 响应（示例 `aygu95dkjdgk8mjk5o0nq22vyomv8xid`）
- 相关源码（页面内联脚本）：
  ```js
  setMaxDigits(130);
  var key = new RSAKeyPair("10001", "", modulus);
  return encryptedString(key, arg);   // arg = 密码明文
  ```
  - 公钥参数：`PublicExponent="10001"`，`modulus`(1024-bit, 见复现脚本常量)
- 运行时变量：注入 `TestPass@2026` 后捕获样本密文
  `9df7e160e9d0d3e23b8fe1fb65db5a91755afcc01e52f226cab2133501ca8b96...`（256 hex）。
- 网络记录：`/auth/needGtCode` 返回 `{"code":2000,"reqId":"...","showValid":true}`。

- 是否启用：否
- 判定原因：纯前端 RSA（Stanford jsbn），无环境指纹 / 无 WASM / 无 JSVMP，无需补环境。
- 触发信号：无
- 补环境建议：N/A

## 验证应对

- 验证类型：密码字段加密（RSA）
- 处理路由：直接本地复现（pycryptodome PKCS1_v1_5），无需补环境、无需人工接力。
- 是否需要人工接力：仅极验(GeeTest)滑块部分需要人工/打码；密码加密复现本身不依赖。
- 识别信号：内联脚本含 `RSAKeyPair` / `encryptedString` / `setMaxDigits`，公钥以 hex modulus 明文给出 → 典型 jsbn RSA。
- 证据包摘要：`assets/repro/dcn_login/repro_dcn_login.py` + 浏览器捕获样本密文。

## 分析过程

- 类型判断：登录接口 → 经典 RSA 密码加密（非签名、非 HMAC）。
- 入口定位：`goLogin.html` 内联脚本中 `encryptedString(key, arg)` 即密码加密入口；`key` 由 `new RSAKeyPair("10001","",modulus)` 构造。
- 环境补丁：无。
- 复现方法：用 pycryptodome 构造 `RSA.construct((n, 0x10001))` + `PKCS1_v1_5`，对密码 utf-8 编码后加密得到 hex 密文。

## 误判点

- 误判点 1：以为是自研加密 / 签名参数。→ 真实原因：标准 jsbn RSA (PKCS#1 v1.5)。识别信号：`RSAKeyPair`/`encryptedString` 函数名。
- 误判点 2：以为需要完整登录（含极验）才能验证加密正确性。→ 真实原因：发送加密 `pwd` 后服务端返回「请先完成图形验证」，恰好证明服务端已成功解密密码字段。
- 误判点 3：以为密文应逐字节与样本一致。→ 真实原因：PKCS#1 v1.5 使用随机填充，每次密文不同，但 `c < n` 且 128 字节结构一致即可。

## 真正原因

- 真正原因：密码经 1024-bit RSA (PKCS#1 v1.5) 加密，公钥明文内联在登录页。
- 识别信号：内联脚本 `setMaxDigits(130); new RSAKeyPair("10001","",modulus); encryptedString(key, pwd)`。
- 修复方式（针对本项目工具链，非站点本身）：无站点修复；本项目新增 `cases/dcn_login_20260708.md`。
- 工具链附带修复：修复 `ch_reverse_generate_report` 的 `unhashable type: 'slice'` bug（后端 `listener.read` 返回 dict 时，下游 `requests[-50:]` 切片报错）。已在 `mcp_service._as_list` 与 `report_generator._coerce_list` 两处加防御。

## 验证结果

- 生成位置：页面内联脚本 `encryptedString(key, 密码明文)`。
- 本地复现方式：
  ```bash
  d:\python_work\venv\Scripts\python.exe assets/repro/dcn_login/repro_dcn_login.py
  ```
- 验证结果：
  - 算法自测 OK：本地 RSA 密钥 encrypt/decrypt 往返一致，密文 128 字节。
  - 与浏览器样本对比 OK：长度/结构一致（均为 128 字节合法 RSA 密文，`c < n`）。
  - 真实请求：`live_login()` 发送加密后 `pwd`，服务端返回 `{"code":9999,"error":"请先完成图形验证","showValid":true}`，与浏览器一致 → 密码字段已被成功解密处理。
  - 完整登录仍需通过极验(GeeTest)滑块（行为验证，不在密码加密复现范围内）。

## 可复用规则

- 规则 1：内联脚本出现 `RSAKeyPair` / `encryptedString` / `setMaxDigits` → 直接判定为 Stanford jsbn RSA，用 pycryptodome `PKCS1_v1_5` 复现，公钥 `n=modulus(hex)`, `e=0x10001`。
- 规则 2：RSA 密文为随机填充，验证时比「长度/结构/范围」而非逐字节相等。
- 规则 3：`/auth/login` 类 GET 登录接口，密码参数常名为 `pwd`/`password`/`enc`，账号多为明文 `name`/`username`。
- 规则 4（工具链）：任何从后端 `listener.read` 取 `requests` 的地方，必须假定返回值可能是 dict，先做 list 规范化再切片。

## 回归说明

- 哪些点容易变：
  - 公钥 `modulus` 可能随站点升级更换 → 重新从页面内联脚本提取 `modulus` 常量。
  - 极验 `gt` 值、是否强制图形验证（`/auth/needGtCode` 的 `flag`）可能调整。
  - 登录端点路径（`/auth/login`）、参数名（`name`/`pwd`/`reqId`/`to`）可能微调。
- 下次升级时先检查什么：
  1. 登录页内联脚本中的 `modulus` 与 `PublicExponent`。
  2. 提交按钮选择器 `#pwdLgn button` 是否变化。
  3. 极验开关与 `gt` 值。

## 踩坑记录

- 误判（密码是自研加密）→ 真实原因（标准 jsbn RSA）→ 识别信号（`RSAKeyPair`/`encryptedString`）→ 修复方式（pycryptodome PKCS1_v1_5 复现）→ 可复用规则（规则 1/2）。
- 误判（需完整登录才验证）→ 真实原因（服务端解密后即报图形验证）→ 识别信号（返回「请先完成图形验证」）→ 修复方式（以该响应作为加密正确性的正面证据）→ 可复用规则（规则 3）。
- 工具链坑（report 生成 `unhashable type: 'slice'`）→ 真实原因（`listener_requests` 为 dict 时 `requests[-50:]` 切片）→ 识别信号（MCP 报告工具报错）→ 修复方式（`_as_list`/`_coerce_list` 规范化）→ 可复用规则（规则 4）。
